# Version 1.0.0

## Summary

Version 1.0.0 is the first stable release of the Next.js FastAPI Foundation. It
provides a reusable, tested connection from a Next.js App Router frontend
through FastAPI and SQLAlchemy to PostgreSQL, with a generated API client,
database migrations, layered tests, and full-stack CI.

This document prepares the release body. The `v1.0.0` tag and GitHub Release are
created only after the release-preparation pull request is reviewed and merged.

## Major capabilities

- Next.js App Router, React, TypeScript, Tailwind CSS, and server-first rendering
- FastAPI with normalized errors, request IDs, health, and database readiness
- Async SQLAlchemy 2, Psycopg 3, PostgreSQL, and Alembic-only schema management
- Deterministic OpenAPI export and generated TypeScript types and operations
- Project Management reference vertical slice across browser, API, and database
- Jest, React Testing Library, pytest, real-PostgreSQL integration tests, and
  Playwright browser-to-database coverage
- Immutable GitHub Actions references, dependency-update automation, protected
  default-branch workflows, and private vulnerability reporting guidance
- Verified GitHub **Use this template** onboarding

## Quality and validation

The generated-template smoke validation passed locally with:

- 152 frontend tests across 14 suites
- 196 default backend tests
- 11 PostgreSQL integration tests
- 1 Playwright E2E test
- a successful production frontend build and backend compilation
- current OpenAPI and generated frontend API artifacts

Hosted Full-stack CI run `30404101906` passed the
`Quality, PostgreSQL, and Playwright` job in the generated private repository.
The release-preparation checkpoint reruns the same repository validation before
the tag is created.

## Template-user expectations

Template users must replace project identity and repository links, configure
environment values and secrets, select deployment targets, define their domain
logic, and establish production operations appropriate to their application.
The included Project feature is a reference vertical slice that may be retained,
renamed, replaced, or removed after another complete slice proves the
architecture.

Keep the existing MIT notice while substantial portions of this foundation
remain. Enable GitHub Private Vulnerability Reporting or provide another real
private reporting channel before publication.

## Known limitations

- Authentication, authorization, multi-tenancy, billing, email, storage,
  realtime features, background jobs, and provider-specific deployment
  configuration are intentionally not included.
- The Project feature demonstrates architecture; it is not a complete
  production project-management product.
- Production database roles, backups, monitoring, scaling, secret management,
  TLS, and deployment topology remain the adopting project's responsibility.
- The frontend dependency graph retains documented development-tooling-only
  findings for GHSA-mh99-v99m-4gvg (`brace-expansion`) through older compatible
  `minimatch` consumers. The repository's dependency regression tests document
  why forcing the patched major would break those tools. These paths are not
  application-runtime or network-input paths.

## Upgrade notes

This is the first stable release, so there is no prior stable migration path.
Existing pre-release adopters should compare their customizations, environment
contracts, generated API artifacts, and Alembic history rather than assuming an
in-place package upgrade.

## Post-merge publication

After the preparation pull request is reviewed and merged, publish from its
exact merge commit:

```bash
git switch main
git pull --ff-only origin main
release_commit=$(gh pr list \
  --repo dmayes77/nextjs-fastapi-foundation \
  --state merged \
  --head release/step-30-v1.0.0 \
  --limit 1 \
  --json mergeCommit \
  --jq '.[0].mergeCommit.oid')
test -n "$release_commit"
test "$(git rev-parse HEAD)" = "$release_commit"
git tag -a v1.0.0 "$release_commit" -m "Release v1.0.0"
git push origin v1.0.0
gh release create v1.0.0 \
  --repo dmayes77/nextjs-fastapi-foundation \
  --verify-tag \
  --title "v1.0.0" \
  --notes-file docs/releases/v1.0.0.md
test "$(git rev-list -n 1 v1.0.0)" = "$release_commit"
gh release view v1.0.0 \
  --repo dmayes77/nextjs-fastapi-foundation \
  --json tagName,name,isDraft,isPrerelease,publishedAt,url
```

Do not run these commands until the reviewed preparation pull request is merged
and local `main` is fast-forwarded to that merge commit.
